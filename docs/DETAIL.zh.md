# 便签滑动窗口上下文

DeepSeek Harness 默认用摘要回收上下文：会话超过压力阈值后，较早的一段历史被替换成一段模型写出的摘要。这意味着每次换窗都要多一次模型调用，而摘要保留什么由模型当场决定。

本插件把它换成由模型自己写的交接便签，以及一个几乎什么都不留的新窗口。

## 变化

装上之后：

1. **便签由模型自己写。** 它决定新窗口必须知道什么——目标、决策及其理由、约束、已被否决的做法、未决问题、下一步动作——并用一次工具调用保存下来。
2. **窗口结束。** 可以是模型主动发起，也可以是 token 压力触发。当前 turn 之前的每一条消息都会离开对话。
3. **下一个窗口几乎是空的。** 只有系统提示、便签、以及正在进行中的本 turn。别的什么都不带。
4. **换窗不消耗模型调用。** 不花 token，同一段历史永远生成同一张便签，重放会话得到一致结果。

被淘汰的消息没有被删除。它们留在会话日志里，仍可按条回查。

## 交接便签

便签主体是模型自己的话，原样带过去。另有一个可选段落记录对话确实做过的事——动过的路径、跑过的命令、失败的工具结果——因为模型可能忘记某个路径，但日志不会。

如果自动换窗发生在模型还没写便签之前，便签会明确说明这一点，只带那些客观事实，绝不编造一份交接。

便签先于其它内容领取字节预算，永远不会被截断到不可读；超出预算的便签会被拒绝并提示合并。

## 感知与回查

- **预算感知。** 模型可以询问距离窗口结束还剩多少 token，以及这个数字来自 Provider 实测还是本地估算。有了它，模型才能在窗口**结束之前**写好便签。
- **归档回查。** 模型可以列出已归档窗口、按精确字面量检索、按 id 读取单条，因此被便签省略的细节仍是一次定向查询的距离。

一段常驻系统提示向模型说明整个闭环怎么用，以及绝不能把它暴露给你。

## 工具只新增，压缩被替换

安装新增四个工具、替换压缩后端。它不拿走任何工具，也不改变你的会话当前使用的 Agent 预设。

在 CLI、headless、SDK profile 上，后端是一个 profile 行：插件停用摘要后端并把自己放在原位。Web 与 Desktop 上，压缩后端属于 Agent 预设，因此插件**原地覆盖** shipped `standard` preset——同一个 id、同一个 order、同一份插件列表——只换掉它的压缩组。没有任何东西需要选择：启用插件、重启，新会话就用便签换窗。

你原有的工具一个不少：在真实 profile 上实测，启用前后从 108 个工具变为 112 个，没有任何一个被移除。

## 你会看到什么

切换是静默的。对话从便签继续，回复里不会提到这次切换。想查事实时，会话日志把每次换窗记录成一对 `compaction/*` 事件，并记下被替换的范围。

## 配置

| 键 | 默认值 | 含义 |
|---|---|---|
| `thresholdRatio` | `0.8` | 触发自动换窗的消息预算占比。 |
| `retainTokens` | `0` | 换窗后保留的原文尾部；`0` 只保留进行中的本 turn。 |
| `noteMaxBytes` | `6144` | 整张便签的字节预算。 |
| `handoffMaxBytes` | `4096` | 模型自写交接段的预算，最先领取。 |
| `derivedAppendix` | `true` | 是否包含客观事实段。 |

段落与工具开关（`noteTool`、`sensingTool`、`historyTool`、`newContextTool`、`guidance`）以及检索与读取上限同样可配置；任何未知键会在加载时报错，而不是被静默忽略。

## 限制

- **便签只等于写进去的东西。** 这正是设计意图——由模型决定——但也意味着写得薄就丢细节。回查工具正是为此存在。
- **不可分割的单个单元无能为力。** 一条独占窗口的超大工具结果或消息，无法靠换窗切开。
- **自带的预设是一份快照。** 它对应本插件所针对版本的内置 `standard` 预设。之后的 DSH 版本可能改动该预设而插件不会察觉，因此请随 DSH 一起升级插件。
- **卸载本插件即恢复摘要后端**，因为切换是组合补丁，不是对已存会话的改写。
